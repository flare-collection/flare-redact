Why log redaction misses errors and objects

Field notes: errors, structs and printf arguments become text after the redaction hook ran. Real output from pino, Go slog and Python logging, and a canary test you can copy.

Switching from fast-redact, pino redact, redact-secrets or deep-redact

Keep your paths and censor value, and also catch the secrets that sit inside strings. Option mapping, tested before and after output, and a speed and coverage benchmark.

PII redaction in JavaScript

Hide secrets in Node.js logs

Redact LLM prompts

Secure MCP tool boundaries

Stop cross-tool placeholder restoration by binding every reversible placeholder to a trusted tool scope.

Control information flow across agent tools

Secure NeMo Guardrails tool execution

One policy, several boundaries

Redaction is most reliable when it happens before a value reaches a logger, external model, analytics SDK, webhook, or tool. Flare Redact uses the same policy shape at each boundary, so a credential is not protected in one path and forgotten in another.
